# 浏览器

Agent 可以控制网页浏览器来测试应用、审计无障碍、把设计转成代码，以及做更多事情。凭借对控制台日志和网络流量的完整访问，Agent 可以调试问题并自动化完整的测试流程。

对于企业客户，浏览器控制由 MCP 允许列表或拒绝列表管理。

## 原生集成

Agent 会在聊天中显示浏览器操作，例如截图和动作，也会显示浏览器窗口本身，可以是独立窗口或内联窗格。

我们优化了浏览器工具，使其更高效并减少 token 用量，同时还包括：

- **高效的日志处理**：浏览器日志写入文件，Agent 可以 grep 并选择性读取。Agent 不再在每次操作后总结冗长输出，而是只读取需要的相关行。这样既保留完整上下文，又把 token 用量降到最低。
- **带图像的视觉反馈**：截图直接与文件读取工具集成，因此 Agent 实际看到的是浏览器状态的图像，而不是依赖文字描述。这有助于更好地理解视觉布局和 UI 元素。
- **智能提示词**：Agent 会收到关于浏览器日志的额外上下文，包括总行数和预览片段，帮助它决定要检查什么。
- **开发服务器感知**：系统会提示 Agent 检测正在运行的开发服务器，并使用正确的端口，而不是启动重复的服务器或猜测端口号。

无需安装或配置任何外部工具即可使用浏览器。

## 浏览器能力

Agent 可以使用以下浏览器工具：

### 导航

访问 URL 并浏览网页。Agent 可以通过访问 URL、跟随链接、在历史记录中后退和前进以及刷新页面，导航到网上的任何地方。

### 点击

与按钮、链接和表单元素交互。Agent 可以识别页面元素并与之交互，对任何可见元素执行单击、双击、右键单击和悬停操作。

### 输入

在输入框和表单中输入文本。Agent 可以填写表单、提交数据，并与表单字段、搜索框和文本区域交互。

### 滚动

在长页面和内容中导航。Agent 可以滚动以显示更多内容、查找特定元素，并浏览较长的文档。

### 截图

捕获网页的视觉呈现。截图帮助 Agent 理解页面布局、验证视觉元素，并向你确认浏览器操作。

### 控制台输出

读取浏览器控制台消息、错误和日志。Agent 可以监控 JavaScript 错误、调试输出和网络警告，以排查问题并验证页面行为。

### 网络流量

监控页面发出的 HTTP 请求和响应。Agent 可以跟踪 API 调用、分析请求载荷、检查响应状态码，并诊断与网络相关的问题。目前仅在 Agent 面板中可用，即将支持到布局中。

## 会话持久化

浏览器状态会根据你的工作区在 Agent 会话之间保持。这意味着：

- **Cookie**：身份验证 cookie 和会话数据在浏览器会话之间仍然可用
- **Local Storage**：存储在 `localStorage` 和 `sessionStorage` 中的数据会保留
- **IndexedDB**：数据库内容在会话之间保留

浏览器上下文按工作区隔离，确保不同项目保持各自的存储和 cookie 状态。

## 使用场景

### Web 开发工作流

浏览器与 Figma、Linear 等工具一起融入 Web 开发工作流。关于如何将浏览器与设计系统、项目管理工具和组件库一起使用的完整指南，见 [Web 开发手册](https://cursor.com/for/web-development.md)。

### 无障碍改进

Agent 可以审计并改进 Web 无障碍，以满足 WCAG 合规标准。

@browser 检查颜色对比度、验证语义化 HTML 和 ARIA 标签、测试键盘导航，并找出缺失的 alt 文本

### 自动化测试

Agent 可以执行完整的测试套件，并截图用于视觉回归测试。

@browser 用测试数据填写表单、逐步点击工作流、测试响应式设计、验证错误消息，并监控控制台中的 JavaScript 错误

### 从设计到代码

Agent 可以把设计转换成带响应式布局的可运行代码。

@browser 分析这份设计稿，提取颜色和排版，并生成像素级精确的 HTML 和 CSS 代码

### 根据截图调整 UI 设计

Agent 可以通过识别视觉差异并更新组件样式来细化现有界面。

@browser 将当前 UI 与这张设计截图对比，并调整间距、颜色和排版以匹配

## 安全

浏览器作为安全的 web view 运行，并由作为扩展运行的 MCP 服务器控制。多层防护保护你免受未经授权的访问和恶意操作。
Cursor 的浏览器集成也已经过多家外部安全审计机构审查。

### 身份验证与隔离

浏览器实现了多项安全措施：

- **Token 身份验证**：Agent 布局会在每个浏览器会话开始前生成随机身份验证 token
- **标签页隔离**：每个浏览器标签页都会获得唯一的随机 ID，以防止跨标签页干扰
- **基于会话的安全**：每次新的浏览器会话都会重新生成 token

### 工具批准

浏览器工具默认需要你的批准。在 Agent 执行之前审查每个操作。这可以防止意外导航、数据提交或脚本执行。

你可以在 Agent Settings 中配置批准设置。可用模式：

| 模式                     | 说明                                                                 |
| :----------------------- | :------------------------------------------------------------------- |
| **Manual approval**      | 逐一审查并批准每个浏览器操作（推荐）                                 |
| **Allow-listed actions** | 与允许列表匹配的操作会自动运行；其余操作需要批准                     |
| **Auto-run**             | 所有浏览器操作立即执行，无需批准（请谨慎使用）                       |

### 允许列表与阻止列表

浏览器工具与 Cursor 的[安全护栏](https://cursor.com/docs/agent/security.md)集成。配置哪些浏览器操作自动运行：

- **允许列表**：指定可跳过批准提示的受信任操作
- **阻止列表**：定义应始终被阻止的操作
- 通过以下路径访问设置：**Cursor Settings > Agents > Auto-Run**

允许/阻止列表系统提供尽力而为的保护。由于提示词注入和其他问题，AI 行为可能不可预测。请定期审查自动批准的操作。

切勿对不受信任的代码或不熟悉的网站使用 Auto-run 模式。Agent 可能会在你不知情的情况下执行恶意脚本或提交敏感数据。

### 浏览器上下文

浏览器以窗格形式在 Cursor 内打开，通过 MCP 工具让 Agent 完全控制。

## 推荐模型

我们建议使用 Sonnet 4.5、GPT-5 和 Auto，以获得最佳表现。

## 企业用法

对于企业客户，浏览器功能通过在 MCP 控制下切换可用性来管理。管理员对每个 MCP 服务器以及浏览器访问都有细粒度控制。

### 为企业启用浏览器

要为企业团队启用浏览器能力：

1. 前往你的[设置仪表盘](https://cursor.com/dashboard/settings)
2. 进入 **MCP Configuration**
3. 切换 “browser features”

配置完成后，组织中的用户将根据你的 MCP 允许列表或拒绝列表设置获得浏览器工具访问权限。

### 来源允许列表

企业管理员可以配置来源允许列表，限制 Agent 可以自动导航到哪些站点，以及 MCP 工具可以在哪里运行。这为安全和合规提供了对浏览器访问的细粒度控制。

必须先为你的组织启用 Browser Origin Allowlist 功能，它才会出现在仪表盘中。联系你的 Cursor 客户团队以申请访问权限。

#### 配置

要配置来源允许列表：

1. 前往你的[管理仪表盘](https://cursor.com/dashboard/settings)
2. 进入 **MCP Configuration**
3. 确保已启用 **Enable Browser Automation Features (v2.0+)**
4. 在 **Browser Origin Allowlist (v2.1+)** 下，点击 **Add Origin**
5. 输入你想允许的来源（例如 `*`、`http://localhost:3000`、`https://internal.example.com`）

将允许列表留空即允许所有来源。每个来源应使用 Add Origin 按钮单独添加。

![MCP Configuration 中显示带有 Add Origin 按钮的 Browser Origin Allowlist 设置](/docs-static/images/agent/browser-origin-allowlist.png)

#### 行为

配置来源允许列表后：

- **自动导航**：Agent 只能使用 `browser_navigate` 工具访问与允许列表中的来源匹配的 URL
- **MCP 工具执行**：MCP 工具只能在允许列表中的来源上运行
- **手动导航**：用户仍然可以手动将浏览器导航到任何 URL，包括允许列表之外的来源（便于查看文档或检查外部站点）
- **工具限制**：一旦浏览器位于不在允许列表中的来源上，浏览器工具（点击、输入、导航）会被阻止，即使用户是手动导航到那里的

#### 边界情况

来源允许列表提供尽力而为的保护。请注意以下行为：

- **链接导航**：如果 Agent 在允许的域名上点击一个链接，而该链接导航到未允许的来源，导航会成功
- **重定向**：如果 Agent 导航到一个允许的来源，而该来源随后重定向到未允许的来源，重定向会被允许
- **JavaScript 导航**：从允许的来源到未允许来源的客户端导航（通过 `window.location` 或类似方式）会成功

来源允许列表限制的是 Agent 的自动导航，但无法阻止所有导航路径。请定期审查你的允许列表，并考虑允许访问那些可能重定向或链接到外部站点的域名所带来的安全影响。
