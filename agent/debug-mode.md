# Debug Mode

Debug Mode 帮助你找到根因，并修复那些难以复现或难以理解的棘手 bug。Agent 不会立刻写代码，而是生成假设、添加日志语句，并用运行时信息定位确切问题，然后再做有针对性的修复。

## 何时使用 Debug Mode

Debug Mode 最适合：

- **你能复现但想不明白的 bug**：你知道有地方不对，但读代码看不出原因
- **竞态条件与时序问题**：取决于执行顺序或异步行为的问题
- **性能问题与内存泄漏**：需要运行时分析才能理解的问题
- **以前能工作的回归**：你需要追踪改变了什么

当常规的 Agent 交互难以处理某个 bug 时，Debug Mode 提供另一种做法：用运行时证据，而不是猜测修复。

## 它如何工作

1. **探索并提出假设**：Agent 探索相关文件、建立上下文，并对可能的根因生成多个假设。

2. **添加插桩**：Agent 添加日志语句，把数据发送到 Cursor 扩展中运行的本地调试服务器。

3. **复现 bug**：Debug Mode 请你复现 bug，并给出具体步骤。这让你留在循环中，并确保 Agent 捕获真实的运行时行为。

4. **分析日志**：复现之后，Agent 查看收集到的日志，根据运行时证据确定实际根因。

5. **做有针对性的修复**：Agent 做出直接针对根因的聚焦修复，常常只是几行代码。

6. **验证并清理**：你可以再次执行复现步骤来验证修复。确认之后，Agent 会移除全部插桩。

## Debug Mode 的提示

- **提供详细上下文**：你对 bug 及其复现方式描述得越多，Agent 的插桩就越好。请包含错误信息、堆栈跟踪和具体步骤。
- **严格按照复现步骤执行**：执行 Agent 给出的步骤，以确保日志捕获到实际问题。
- **需要时多次复现**：多次复现 bug 可能帮助 Agent 识别竞态条件这类棘手问题。
- **具体说明预期行为与实际行为**：帮助 Agent 理解应该发生什么，以及实际发生了什么。

## 切换模式

- 使用 Agent 中的模式选择下拉菜单
- 按 Shift+Tab 快速切换
