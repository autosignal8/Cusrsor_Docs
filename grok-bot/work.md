# 使用 Grok Bot

日常与 Bot 协作的全部内容：[创建和管理它们](https://cursor.com/docs/grok-bot/work.md#bots)、[发消息与协作](https://cursor.com/docs/grok-bot/work.md#messaging-and-collaboration)、[它们共用的计算机](https://cursor.com/docs/grok-bot/work.md#the-computer-and-apps)，以及[把完成的工作变成 Skill 和例程](https://cursor.com/docs/grok-bot/work.md#skills-and-routines)。

## Bot

Bot 是一个持久的 AI 队友，有名字、有职责、有自己的对话，以及随时间形成的工作上下文。当工作有不同的目标、工具集合、工作方式、批准边界或重复计划时，单独创建一个 Bot。人才搜寻、费用管理和 Bug 复现这类职责会给 Bot 指导，并让保存的上下文可以复用；通用助手两者都做不到。用可操作的说法描述角色：

> 负责每周的客户健康审查。拉取产品用量和支持信号，标出流失或扩张的证据，并为客户成功团队生成一份带链接的观察名单。未经批准，绝不联系客户或更改账户。

### 创建 Bot

1. 在侧边栏选择 **New Bot**（**+** 按钮），或按 Cmd+N。在团队中，**+** 按钮会打开菜单；选择 **Create a Bot**。为 Bot 命名，选择形状和颜色，然后选择 **Create**。
2. 在第一条消息中给出 Bot 的职责、来源和批准边界，并让它记住。发送一项有明确完成标准的真实首个任务；起步提示词见[使用场景](https://cursor.com/docs/grok-bot/use-cases.md)。
3. 要重命名 Bot、添加标签或更换图片，点击聊天顶部的 Bot 名称以打开详情。见[更改 Bot 的名称、图片和职责](https://cursor.com/help/grok-bot/edit-bot.md)。

当某项工作应当有长期负责人时，你已有的 Bot 也可以建议或创建一个职责聚焦的 Bot。

### 编辑 Bot

当你发现一项应影响以后工作的持久偏好、边界或职责时，告诉 Bot 并让它记住。针对特定任务的指令使用普通消息：

- **长期规则。**「从现在起，未经批准绝不发送外部消息。」
- **任务。**「为这十二个客户起草跟进。」

[共享 Bot](https://cursor.com/help/grok-bot/shared-bots.md) 还有一段描述，其所有者或 Manager 在 Bot 详情的 **About** 下编辑。

### 整理你的名单

用 **Pin** 把活跃的 Bot 固定到侧边栏顶部，并用分区按项目、客户或业务给它们分组：右键点击一个 Bot，选择 **Move to new section**；已有分区后选择 **Move to**。分区会在桌面和 iOS 之间同步。**Hide from sidebar** 会把 Bot 从主列表中移除，但不会删除它的工作，也不会暂停它的例程；从 **Hidden Bots** 用 **Show in sidebar** 恢复。在 iPhone 上，**Duplicate** 一个 Bot 可以把同一角色复用到不同范围，例如每个地区一个客户健康 Bot：副本会带上资料、设置、已启用的 Skill、例程和头像，但不带对话历史、学到的记忆或附件，因此在分配工作之前先重命名并给出新的范围。

### 分享 Bot

当别人应当从同一个 Bot 起步时，分享一个公开链接。链接会暴露共享配置（身份、描述、Skill 和例程），因此请先移除 API 密钥、内部 URL 和客户数据。接收者会把一份副本加到自己的账户；他们永远得不到你的计算机、登录或对话历史，并且添加共享 Bot 即表示接受此时显示的第三方 bot 条款。如果要给你的团队一个可以一起聊天的 Bot，而不是每人一份副本，请[分享 Bot 本身](https://cursor.com/help/grok-bot/shared-bots.md)。

在 Teams 方案和 Enterprise 方案上，管理员控制成员是否可以公开发布 Bot 模板。见[模板分享](https://cursor.com/docs/grok-bot/teams.md#admin-controls)。

### 删除 Bot

删除 Bot 会移除它的资料、对话和例程。共享计算机上的文件和登录不是按 Bot 隔离的，可能仍然留在那里；请单独清理。如果以后可能还需要这些工作，改为隐藏该 Bot。

### Bot 会记住什么

Bot 会保留稳定的偏好、重要事实，以及来自其工作的摘要，从而可以长期维持一个角色，而不必重放每一条先前的消息。记忆不能替代权威来源：把会变化的事实留在来源系统中，对于重要决策请让 Bot 引用来源或重新打开当前数据，直接纠正过时的假设，并用批准和 [Auto-review 规则](https://cursor.com/docs/grok-bot/security.md#approvals-and-auto-review) 支撑安全边界，而不是只靠记忆。

## 消息与协作

Grok Bot 的设计是让你感觉像在给队友发消息。请求保持自然，但要把结果和决策边界说清楚：Bot 可以改什么，以及它必须在哪里停下来等你。

### 给 Bot 发消息

在对话中，你可以粘贴文本、链接和图像，附加文件，按名称要求一个已保存的 [Skill](https://cursor.com/docs/grok-bot/work.md#skills-and-routines)，用 `@` 提及一个 Bot、分组、例程或应用，回复或对消息做出反应，并在工作进行中再发送另一条指令。记录会在普通消息旁边显示工具活动、计算机操作、创建的文件、问题和批准请求。

你直接发出的消息优先于后台工作，并且可以改道当前回合。当工作应立即结束时发送「立刻停止」；停止不会撤销 Bot 已经完成的操作。

### 附加文件和链接

支持的输入包括图像、音频、视频、PDF、Office 文档、CSV、JSON、YAML、源代码、HTML、电子邮件文件和笔记本。过大、加密、损坏或不常见的文件可能无法读取；请把不常见的格式导出为 PDF、CSV、纯文本或图像。

| 限制 | 值 |
| --------------------------------- | ------------------------------------ |
| 每条消息的附件数（桌面） | 20 |
| 图像 | 每个 25 MB，每条消息合计 200 MB |
| 文档、音频和其他文件 | 每个 250 MB |
| 视频 | 每个 1 GB |

告诉 Bot 每个附件是什么、如何使用：

> 这份 PDF 是已签署的政策。这份电子表格是本月的交易。对照政策核对电子表格，为每个例外引用相关政策章节，并返回一份新的电子表格和一段简短摘要。不要修改原件。

当 Bot 能从它的计算机或已连接应用访问该页面时，粘贴链接；如果页面是私有的，请[通过计算机登录](https://cursor.com/docs/grok-bot/work.md#take-over-for-sensitive-steps)或连接该应用。在输入凭证或批准外部操作之前，始终检查链接的目的地。

### 群聊

当几个 Bot 需要一个共享结果和可见的交接时，使用群组。选择 **New chat**，选择二到六个 Bot，并描述结果以及谁负责下一步。正常书写，让 Bot 决定谁来回应；输入 `@` 把请求交给一位队友，把 `@everyone` 留给全组更新。一次有用的开场会为每个阶段指定一位负责人：

> @Researcher 收集原始材料，并为每条主张加上链接。@Writer 把发现整理成发布草稿。@Reviewer 对照来源检查草稿，只列出阻塞性问题。不要发布任何内容。

你在群组中的消息可以包含附件。Bot 发给群组的交接消息只有文本，因此当队友必须查看图像时，Bot 应把图像直接发给另一个 Bot。

### 在 Bot 之间交接工作

Bot 可以向另一个 Bot 发送异步消息，对方会被唤醒、处理请求，并可以稍后回复；你会在对话中看到这次交接。当一个 Bot 负责来源系统、另一个负责交付物，或一项长时间运行的工作应在没有你协调每一步的情况下继续时，交接效果很好。要求每个阶段只有一位负责人；并行交接会造成重复工作和不必要的更新。

交接需要一个代表某一个人行事的 Bot。从应用或你自己的 Slack 私信中，任何 Bot 都可以交接工作。从 Slack 频道讨论串中，只有[共享 Bot](https://cursor.com/help/grok-bot/shared-bots.md)可以交接，并且是代表提及它的那个人。见[Bot 能从 Slack 给其他 Bot 发消息吗？](https://cursor.com/help/grok-bot/group-chats.md#can-a-bot-message-other-bots-from-slack)

### 要求可审查的结果

说明产物及其验收标准：带有来源链接的文档、列已定义的电子表格、截图和日志文件夹，或尚未发送的草稿。对于重要工作，请让 Bot 分开写出在来源系统中找到的事实、假设、已经完成的操作、等待批准的操作，以及未解决的问题。

有力的结果可以独立审查：直接的来源链接、能看到相关状态的截图、时间戳、简洁的操作日志，以及 Bot 无法核实的内容的明确清单。不要只靠截图判断变化很快的数据。生成的文件和链接会显示为卡片，你可以预览、保存，或用反馈回复；请让 Bot 修改现有产物，而不是制作互不关联的副本。

当反馈针对某一项结果或某一条批准请求时，在讨论串中回复；反应只用于轻量确认。单独一个反应不应承载安全关键的决定。搜索和命令面板可以在你的各个 Bot 中查找先前的消息、文件、链接和例程。推出期间搜索的可用性可能不同；如果跨对话结果不可用，打开相关 Bot 并使用它的对话历史。

## 计算机与应用

你的 Bot 在一台持久的云端计算机上工作，配有浏览器、命令行和文件系统。合上笔记本电脑后工作仍会继续，文件、登录和浏览器会话会在任务之间保留。

你账户上的每个 Bot 都使用同一台计算机：浏览器会话、文件和命令行凭证是共享的，一个 Bot 可以接上另一个 Bot 保存的工作继续做。每个 Bot 有自己的屏幕，因此几个 Bot 可以并行使用浏览器和桌面工具（每个屏幕一次一项计算机操作任务），但这些屏幕是工作界面，不是安全边界。如果另一个你的 Bot 不应当能使用某项凭证，就不要把它放在这台计算机上。用户之间的隔离是严格的：每个用户的计算机是专用的，并且在硬件上隔离。见[用户如何被隔离](https://cursor.com/docs/grok-bot/teams.md#how-users-are-isolated)。

### 观看计算机

点击对话右侧面板中的计算机预览，即可打开计算机，观看点击、输入、导航和当前状态。工作继续时你可以离开预览；关闭应用不会停止云端工作。

### 为敏感步骤接管

要登录时，Bot 会先使用保存在 [Vault](https://cursor.com/help/grok-bot/secrets.md#what-is-vault) 中的登录，然后是已连接的密码管理器（如 1Password），再通过 Secure Form 向你索取。来自 Vault 和 Secure Form 的值会填入页面，而 Bot 看不到它们。当站点通过电子邮件发送一次性验证码时，Bot 可以从已连接的 Gmail 或 Outlook 账户，或从它自己的收件箱读取。结账时，它可以使用保存在 Vault 中的卡、你在 Secure Form 中输入的卡，或已连接的钱包，如 Link、X Money 或 Shop Pay。

当表单无法完成该步骤时，Bot 会把计算机交给你：单点登录、通行密钥、它无法通过的 CAPTCHA、另一台设备上的批准、二维码，或银行卡验证。接管控制，只完成被挡住的那一步，然后告诉 Bot 继续。已登录的会话会为以后的任务保留，并在你的各个 Bot 之间共享。有些站点会使会话过期或重新验证；请让 Bot 暂停并通知你，而不是绕过检查。

对于 API 密钥或其他机密，在 Bot 询问时把它输入安全机密卡片：字段是掩码的，该值不会写入聊天，也不会展示给 Bot。绝不要把密码或一次性验证码粘贴到普通聊天中。见[安全存储机密](https://cursor.com/help/grok-bot/secrets.md)。

### 连接应用

应用给 Bot 一种结构化的方式来使用 Gmail、Notion 和 Slack 等服务；当存在这种方式时，它比在网站上点击更可靠。在侧边栏打开 **Connect apps**，或跟随聊天中的 **Connect** 卡片，然后在浏览器中完成提供商登录；设置步骤和已知问题见[连接应用](https://cursor.com/help/grok-bot/connect-apps.md)。

- **应用是账户范围的。** 已连接的应用可供你运行的每个 Bot 使用。队友的[共享 Bot](https://cursor.com/help/grok-bot/shared-bots.md)在使用你的账户之前会询问。
- **应用登录不会留在计算机上。** OAuth token 保存在 Cursor 的连接器后端，Bot 调用工具时不会收到这些 token。
- **团队策略适用。** 被团队连接器策略阻止的应用会显示 **Disabled by team admin**。阻止一个应用并不会阻止该服务的网站。关闭这第二条路径需要 **Network Controls**，且仅限 Enterprise。见[网络策略](https://cursor.com/docs/grok-bot/security.md#network-policy)。

### 文件与工作区

计算机在 `/workspace` 有一个共享工作区。把持久的项目文件放在那里，并用清晰的项目文件夹组织。文件、浏览器状态和受支持的登录会在正常的计算机更新和恢复中保留；把临时目录、手动安装的软件包和未提交的应用状态视为可替换的，并把重要结果复制到工作区或附加到对话中。

### 更新、恢复或重置

应用和计算机是分开更新的。当计算机无法访问时，先从破坏性最小的选项开始：

1. 从错误状态重试，或重新打开对话。
2. 重启 Grok Bot 应用，并检查是否有应用更新。
3. 当无法访问的状态提供该选项时，选择 **Recover Grok Bot's Computer**。
4. 在 **Settings** > **Computer** 中，使用 **Update Bot's Computer** 移到最新版本。
5. 只在万不得已时，在同一区域使用 **Reset Bot's Computer**。

软件更新只会刷新 Grok Bot 的软件，并保留已安装的应用。计算机更新会重建计算机，保留文件和登录，但移除已安装的应用和软件包。Recover 和 Reset 都会根据你上次保存的数据重建计算机；如果在保存之前无法访问计算机，非常近期的改动不会回来。对话存储在计算机之外，因此即使重置也会保留。见 [Grok Bot 计算机](https://cursor.com/help/grok-bot/computer-recovery.md)。

### 你的本地计算机是分开的

云端计算机与你面前的这台机器是分开的。Bot 只有在本地执行策略下才会在你的本地计算机上运行命令：默认每次命令都需批准，可以设为始终允许、每次询问或从不。该策略是独立的控制，与管理云端计算机上工作的批准分开。见[本地执行](https://cursor.com/docs/grok-bot/security.md#local-execution)。

## Skill 与例程

Skill 是一组可复用的指令，说明如何完成一项任务。例程告诉一个 Bot 何时运行工作流，可以按计划，也可以在受支持的事件之后。先做一次一次性任务，让它可靠，把方法保存为 Skill，然后再自动化。

### 保存 Skill

Skill 会捕获步骤、决策规则、预期输出和安全边界，并且可以在你的各个 Bot 之间使用（Bot 可能仍需要相关的应用或登录）。直接提出要求：

> 把我们用于这项任务的流程保存为一个名为「每周客户健康」的 Skill。包含来源系统、风险定义、输出格式，以及联系客户始终需要批准这条规则。

一个有用的 Skill 会说明何时使用它、所需的输入和访问权限、工作顺序、如何验证结果、返回什么，以及什么需要批准。要使用 Skill，按名称向 Bot 提出。如果 Bot 找不到某个私有 Skill，在侧边栏打开 **Connect apps**，选择标题旁边的已连接数量，并在 **Private skills** 下为当前 Bot 启用它。

### 通过演示教授工作流

与其描述每一步，不如演示一次浏览器工作流，让 Bot 把它变成一份 Skill 草稿。在一对一对话中打开计算机视图，选择 **Teach a task**，描述结果，然后执行工作流。教学会记录最多十分钟的可见计算机交互，不会录制麦克风音频；演示中不要包含机密，凭证请使用安全机密请求。学到的 Skill 是草稿：补上决策规则、失败处理和批准边界，然后在安全的输入上测试，再安排计划。

**Teach a task** 正在逐步推出。如果看不到该控件，请让 Bot 根据书面说明和一项已完成的任务创建 Skill。

### 创建例程

向应当负责这项重复工作的 Bot 提出：

> 每个工作日上午 8:00，针对当前客户名单运行「每日客户风险」Skill。在这个对话中发布一份带链接的观察名单。不要联系客户。如果来源数据不可用，报告失败，而不是使用旧数据。

确认负责的 Bot、计划和时区、输入来源、预期结果、批准边界，以及来源缺失时会发生什么。例程在云端运行，即使你合上笔记本电脑。删除例程会停止以后的运行，并且无法撤销。

Cursor 账户集成也可以从事件启动例程，例如 Slack 消息或 GitHub 通知；它们与 Slack 或 GitHub 应用是分开的。定义狭窄的匹配规则和清晰的响应，例如「当 `#customer-escalations` 中的一条消息包含工单链接和短语 'needs repro' 时，在 staging 中复现该问题，并在这个对话中发布一份复现材料包」。避免「每条新消息」这类宽泛的监听器，它们会产生噪音、消耗用量，并对无关输入采取行动。

### 测试和管理例程

创建或编辑例程后使用 **Test**，并审查它是否选择了当前输入、符合输出格式、保留了来源轨迹、停在预期的批准点，并把失败状态写清楚。

测试运行会做真实的工作。它可以浏览网站、更改文件，并调用已连接的工具。使用安全的输入，并把写入操作留在批准之后。

通过在聊天中询问 Bot 来创建和更改例程。要在桌面上审查它们，点击聊天顶部的 Bot 名称以打开详情。例程在 **Details** 标签页上。打开一个例程以阅读它的 **Instruction** 和 **When to run**。右键点击例程可以 **Pause** 或 **Resume**、**Test**、在聊天中 **Edit**，或 **Delete**。Webhook 例程还会在那里显示 **Webhook**。在手机上，Bot 的资料会列出它的例程以及 **Run history**。离开较长时间后，Grok Bot 可能会询问是否继续运行例程，如果你不回应就暂停它们。关于计划、Slack 触发器和 webhook，见[例程](https://cursor.com/help/grok-bot/routines.md)。

例程获得信任的方式与人一样：先自动化准备，再自动化执行；发送、购买、删除、发布和生产变更留在批准之后；来源缺失或过时时要报告，而不是绕过；网站、应用或来源格式变化后要重新测试。
