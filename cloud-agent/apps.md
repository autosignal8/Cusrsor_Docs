# 应用

[Cloud Agents](https://cursor.com/docs/cloud-agent.md) 可以构建一个可用的 Web 应用，例如仪表盘、门户或微站点。你描述想构建的内容，Cursor 负责托管、数据库、身份验证和密钥。

## 开始使用

请明确说明你希望 Cursor 构建一个应用。你可以从零开始，这会在 [Cursor Origin](https://cursor.com/docs/origin.md) 上创建一个新仓库，也可以请 Cursor 从现有的 GitHub 仓库部署应用。请记得使用 Cloud Agent；本地不支持此功能。

示例提示词：

- “做一个应用，把我们每周的注册量显示为仪表盘，包含一张图表和一张可以按方案筛选的表格。”
- “做一个内部应用，让我的团队可以提交缺陷报告并跟踪其状态。”
- “为我们的产品发布做一个微站点，带一个收集邮箱的注册表单。”
- “把这个仓库部署为一个应用。”

当 Cursor 准备好应用后，它会显示一个托盘，你可以在其中预览应用并发布。发布时，你选择应用的 URL（以后可以更改），Cursor 会运行一系列确定性的和由 Agent 执行的安全检查。如果全部检查通过，Cursor 会返回一个可访问的链接。如果没有通过，它会列出应用部署前需要修复的内容。让 Agent 修复这些问题，然后再次发布。在你选择发布之前，任何内容都不会上线。

## 工作原理

- **托管。** Cursor 把每个应用部署在它为你的团队创建的专用账号中；如果是个人方案，则为你创建。每个托管账号都与其他所有团队和用户的账号相互隔离。
- **数据库。** 如果应用需要数据库，Cursor 会自动为它置备一个 Postgres 数据库。
- **身份验证。** 私有应用和团队应用位于 Cursor 登录之后，因此只有你共享给的人才能打开它们。个人方案的用户可以公开共享应用，这不需要 Cursor 身份验证。
- **密钥。** 当你希望应用使用你自己的资源，或连接到其他系统（例如数据仓库）时，Cursor 会向你询问它所需的密钥。Agent 永远看不到这些值。在大多数情况下，团队管理员在[应用仪表盘](https://cursor.com/dashboard/apps#secrets)中创建团队密钥。如果你有权创建个人密钥，可以添加自己的密钥。

你可以自带资源和集成。在构建应用时，或在[应用仪表盘](https://cursor.com/dashboard/apps#secrets)中，为它们配置密钥和访问密钥。

## 共享

| 可见性 | 谁可以打开 |
| :---------------- | :----------------------------------------------------------------------- |
| 你邀请的人 | 只有你，或已登录 Cursor 的特定团队成员和用户组 |
| 团队 | 你和你的整个 Cursor 团队，且已登录 Cursor |
| 公开 | 任何拥有链接的人 |

对于 Teams 和 Enterprise，公开共享默认关闭。团队管理员可以在[应用仪表盘](https://cursor.com/dashboard/apps#danger-zone)中开启。

## 用于 Grok Bot 和脚本的 API 密钥

私有应用和团队应用位于 Cursor 登录之后，自动化工具无法直接通过。Cursor API 密钥让 Grok Bot、脚本、CI 作业等可以像另一位已登录用户那样使用应用。

### 工作原理

- **个人 API 密钥**可以打开其所有者能够打开的应用。
- **团队 API 密钥**只能打开已授权给它们的团队应用。
- **公开应用**对两种密钥都开放，就像对普通访问者一样。

不被允许进入的密钥会像没有访问权限的用户一样处理，因此调用方会得到登录重定向。

### 通过 HTTP 请求头使用

在每次请求的 `x-cursor-app-token` 请求头中发送密钥：

```bash
curl -H "x-cursor-app-token: $CURSOR_API_KEY" https://<your-app-url>
```

该密钥只能作为请求头使用。没有查询参数，也没有 cookie，因此你的工具必须在每次请求上设置该请求头。

使用密钥发起的请求会被标记为自动化请求，并标识该密钥，而不会标识某个人。在[应用仪表盘](https://cursor.com/dashboard/apps/security/api-keys)中查看与应用关联的全部 API 密钥。

## 安全与控制

[应用仪表盘](https://cursor.com/dashboard/apps)列出你创建的应用以及共享给你的应用。团队管理员可以看到团队中的每个应用和密钥，并且可以取消发布任何应用。

每次发布前都会运行四项检查。即使安全审查关闭，它们也始终开启：

- **阻止写在应用文件中的密钥。** 如果某个文件包含 API 密钥或访问 token，则停止发布。
- **阻止凭证文件。** 如果包含私钥、服务账号密钥，或带有身份验证 token 的文件，则停止发布。
- **永不发布 .env 文件。** 把 `.env` 文件排除在发布内容之外。
- **永不发布 source map。** 移除 source map，使访问者无法阅读原始源代码。

在这些检查之外，AI 安全审查会阅读应用的文件，并在应用上线前阻止严重问题。团队管理员可以在[应用仪表盘](https://cursor.com/dashboard/apps#security)中向审查提示词添加自己的说明。自定义说明可以增加规则，但不能移除 Cursor 的内置检查。

团队管理员还可以：

- 为团队开启或关闭应用。
- 允许或不允许公开应用。不允许时，会把现有的公开应用改回团队可见性。
- 允许或不允许 API 密钥打开应用。
- 批准被审查阻止的发布，但恶意代码、硬编码密钥或泄露的凭证除外。

这些设置的更改会记录在团队的审计日志中。

## 可用性

应用适用于所有可以访问 Cloud Agents 的付费方案。

我们仅提供技术和工具供你使用，不提供任何陈述或保证，也不对你的应用负责，包括你的提示词和任何输出。应用的发布并不构成我们的认可。如果子域名、关联账号或已发布的应用违反这些条款、约束你账号的条款或[可接受使用政策](/acceptable-use-policy)，或出于业务、财务或法律原因，它们可能会被撤销、终止、移除或暂停。你也同意，托管独立于我们的服务，并且不属于我们的服务，按“现状”和“可用时”提供。
